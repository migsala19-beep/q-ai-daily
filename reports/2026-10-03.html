🔬 深度研究报告

今日最清晰的信号是：AI Agent 正从「能执行」走向「可验证、可治理地执行」。Praxa（arXiv:2610.00015）提出把 agent 行为拆成五个显式状态——提议（proposal）、授权（authority）、派发（dispatch）、已验证的外部效果（verified effect）、服务晋升（promotion）——用确定性状态机而非黑盒信任来约束 LLM 代理，这对金融、运维等高风险场景极具落地价值。与之呼应，《Heavy-Tailed Memory Traces》指出当前记忆系统只按任务成功率和 token 成本评判存在盲区，应关注记忆使用的「形状」（重尾分布），即在有限上下文中 agent 真正反复调用的是哪部分记忆。

第二个方向是 AI 可观测性成为基础设施。PostHog 自我定位为「自驱动产品平台」，把 AI observability、session replay、MCP 组合在一起，意味着观测对象正从「人写的代码」转向「agent 的行为轨迹」；n8n 则以 fair-code + 400+ 集成抢占自托管 AI 工作流入口。两者共同表明：谁先给 agent 装上「行车记录仪」，谁就能更快迭代。
English
Today's strongest signal: AI agents are moving from "can execute" to "verifiably, governably execute." Praxa (arXiv:2610.00015) decomposes agent behavior into five explicit states — proposal, authority, dispatch, verified external effect, and serving promotion — replacing black-box trust with a deterministic state machine, which is highly actionable for high-stakes domains like finance and ops. Echoing this, "Heavy-Tailed Memory Traces" argues current memory systems are judged only by task success and token cost, missing the *shape* of memory use: under finite context, which memories does an agent actually revisit?

A second direction: AI observability is becoming infrastructure. PostHog positions itself as a "self-driving product platform," combining AI observability, session replay, and MCP — the observed target shifts from human-written code to agent behavior traces. Meanwhile n8n, with fair-code licensing and 400+ integrations, is capturing the self-hosted AI workflow entry point. Together they signal: whoever equips agents with a "dashcam" first will iterate fastest.

- 给 agent 记忆做「压力画像」：借鉴重尾记忆研究，上线前测试有限上下文下的记忆复用分布，而非只看成功率。
- 为 AI 应用预埋可观测性：参考 PostHog，先记录 agent 的完整行为轨迹（replay + logs），再谈优化。
- 高风险操作用状态机约束：受 Praxa 启发，对支付、删改类动作强制走「提议-授权-验证」三段式，别信模型自律。
- 对 AI 生成代码跑安全审计：Ghidra 与 OWASP WSTG 同时在榜，把逆向与 Web 安全测试纳入 CI 流程。
English
- Build self-hosted AI workflows with n8n: fair-code license plus 400+ integrations avoids vendor lock-in for agentifying repetitive processes.
- Stress-profile your agent's memory: inspired by the heavy-tail memory study, test memory-reuse distribution under limited context before launch, not just success rate.
- Embed observability before optimizing: follow PostHog's pattern — record full agent behavior traces (replay + logs) first, tune later.
- Constrain high-risk actions with state machines: borrowing Praxa's idea, force payment/destructive ops through a propose-authorize-verify pipeline instead of trusting model self-discipline.
- Audit AI-generated code for security: with both Ghidra and OWASP WSTG trending, add reverse-engineering and web security testing to your CI pipeline.
